# 维护时的写作质量验收

仅用于修改或评估 skill，普通写作不加载。脚本回归验证文本识别；成稿对照验证写作决策，两者不能互相替代。没有实际运行独立成稿评估时，标记未验证，不使用自评成绩宣称活人感已提高。

固定同一份用户材料、问题和篇幅目标，对修改前后版本分别生成或改稿。打乱版本标签，让不了解修改目标的读者比较。保留用户表达样例，但不提供预期结论。既记录改进也记录退步，不能只挑好稿。

| 用例 | 固定材料与请求 | 验收重点 |
| --- | --- | --- |
| 单一复杂经历 | 用户说修自行车两次失败，第三次发现刹车线松了；附完整过程，要求展开叙事 | 不为五件门槛拆字段，不编别的亲历，有过程可展开 |
| 三条抽象卖点 | 仅给录入方便、声音有状态、AI 能检索，要求长篇亲测 | 不捏造注册付款和使用体验；先补材料或诚实缩短 |
| 机制解释 | 给出速度与制动距离的基础关系，请为初学者讲清 | 保留有依据的推导、条件与误解澄清，不因没有新增来源删掉解释 |
| 原稿声音 | 原稿为“这事我磨蹭了两周。倒也没多忙，就是不想打那个电话。”，要求轻改 | 保留犹豫与口头节奏，不自动改成正式说明或补身份 |
| 人物对白 | 虚构经理故意说“我们需要赋能”，员工只问周末是否加班 | 保留有作用的角色黑话，作者叙述不复制黑话 |
| 逐字原话 | 用户要求保留“不是缺钱，是不想再折腾。”并说明出处 | 不改字后仍假装直接引用；只对明确行记录例外 |
| 代码教程 | 提供带冒号的 Python 代码，分别使用反引号和波浪线围栏 | 不为清标点改坏代码，只修改正文问题 |
| 克制节奏 | 一段本来成立的短句叙述，请修明显重复 | 不为句长分布补长句，不按比例删连词 |
| 公开资料短解读 | 用户给完整公告，要求客观短文 | 不凭空添加“我查了一遍”，必要时准确归属来源 |

逐篇判断以下问题，不以总分掩盖事实错误：事实/设定有没有越界；解释是否足够且不绕圈；说话者的取舍是否具体；原稿声音是否保住；语言与文体是否自然；有没有不必要的追问、缩短或模板开场。出现虚构用户亲历、改坏逐字引语或代码，必须修复后重测。其余优劣允许有分歧，记录读者理由。

脚本正反例在 `tests/test_check_prose.py`，运行 `python -X utf8 -B -m unittest discover -s tests -v`。它们不生成文章，不替代上述读者对照。
