# 文案与图片的衔接

本文件只在图文任务涉及新写或实质改文案时读取。平台负责形式与视觉，包内 [human-writing](../human-writing/SKILL.md) 负责材料、文字与改稿，根技能负责 API、图片检查、session 和 manifest。安装整个 skillsvc-image 包即可使用，不依赖其他目录的同名技能。不为独立纯文字请求自动扩展出付费图片。

## 何时使用

- 公众号文章加配图、小红书/贴图号主题创作、参考资料原创改编、跨平台图文改编、用户要求去 AI 味并配图：使用。
- 已有定稿只配图、仅公众号封面、普通生图、参考图生图、仅换背景/改构图/替换指定字句：跳过。
- 卡片拆分只复制现有句子时，不改原稿。需要新写概括、过渡或大幅压缩时，仅对这些新增文字使用模块，不把用户的全文重新写一遍。明确要求逐字保留而布局放不下时，优先调整布局或分卡，不静默删字或增加用户未要求的图片数量。

## 执行顺序

1. 先确定目标平台、用户授权的写作范围、原文必须保留的部分与图片数量约束。参考资料来自公众号不代表目标就是公众号。
2. 调用包内写作模块，按其路由只读当前文体所需资料。平台的短文、卡片、清单形式优先于默认论坛长帖；事实边界与用户原意始终保护。不伪造亲历、效果、数据或检索动作。
3. 完成初稿后读取包内 `references/revision.md`，保护当前作品声音并改稿。公众号/普通文章保存 `article.md`；小红书与贴图号保存 `post.md`。已有明确要求不重复索要确认；材料真正不足时按写作规则补查、集中追问或缩短。
4. 平台确定插图位置或卡片顺序。卡片的准确可见文字写入 `card-copy.md`，每张以对应 `asset_id` 作标题，例如 `## card-02`；定稿句子可复制，概括必须保留条件、数字、否定和引用归属。非用户要求，不机械加总结卡或互动诱导。
5. 调用 `python -X utf8 /技能包绝对路径/human-writing/scripts/check_prose.py /稿件绝对路径`。新写文章检查 article.md；新写帖子检查 post.md 与 card-copy.md。局部改写时只检查新写文字，保留原文不受风格门槛阻塞。短稿也可运行；warning 不要求清零，必要原话等用有理由的具体行豁免。细则见 [checker.md](../human-writing/references/checker.md)。纯视觉 prompt、参数字段和内部规划不作为成稿检查。
6. 文案稳定后才构造视觉 prompt。准确可见文字从定稿复制，画面描述可以扩展构图但不能改变事实。事实型示意图不得伪装成真实照片、亲测截图或人物现场。
7. 根技能按资产依赖生成并查看图片，逐字核对可见文字、含义与排版。错字通过对应资产 session 修正，不为通过检查改坏已定稿文案。只修改用户要求或确有错误的资产，不整批重复生成。

写作模块只返回稳定文案及必要的来源/保留约束，不管理图片状态。平台按共享生成契约输出资产规格。CLI 的 `generated` 不是文案审核或视觉 QA 通过；相关检查结果记录到已有 visual-plan.md 或 outline.md，不把内部检查笔记塞进文章。

编辑后文案有实质变化时，先更新可见文字定稿、outline/visual-plan 和受影响 prompt，再对相应 asset_id 编辑；沿用原 session，不把其他卡片改成同一个编辑会话。局部替换指定文字不重新触发全文写作。只改变画面时不动文案。

## 包内维护

写作规则只维护在 `human-writing/`，两个平台不要再各复制一套禁词或句法规则。其相对路径均以该目录为基准。包内测试运行 `python -X utf8 -B -m unittest discover -s human-writing/tests -v`；写作质量评估见 [evaluation.md](../human-writing/references/evaluation.md)。测试通过不证明成稿自然度，尚未执行的模型/读者对照必须标明未验证。
